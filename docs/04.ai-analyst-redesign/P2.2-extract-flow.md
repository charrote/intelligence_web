### Step 2：实现抽取失败重试逻辑

在 `scheduler.py` 中，为抽取任务增加失败重试处理：

```python
def _run_extract_cycle():
    """抽取任务轮询"""
    from core.db import get_setting
    from core.scheduler.extraction_engine import extract_all_pending

    enabled = get_setting("scheduler.extract_enabled", "1")
    if enabled == "0":
        return

    logger.info("[extract_cycle] Running extraction cycle")

    try:
        result = extract_all_pending()

        if result["processed"] > 0:
            logger.info(f"[extract_cycle] Processed {result['processed']} intel(s): "
                       f"success={result['success']}, failed={result['failed']}")

        _update_scheduler("last_extract_time", _now_iso())
        _update_scheduler("extract_success_today",
                         result["success"] + get_setting("scheduler.extract_success_today", "0"))

    except Exception as e:
        logger.error(f"[extract_cycle] Fatal error: {e}")
```

### Step 3：添加清理逻辑

调度器每天 08:00 执行一次数据清理（删除 30 天前的 report_run 记录）：

```python
def _run_cleanup():
    """每日清理过期数据"""
    from core.db import get_db_path, get_setting

    db_path = get_db_path()
    keep_days = int(get_setting("report.retention_days", "30"))

    with get_db(db_path) as conn:
        cutoff = datetime.now() - timedelta(days=keep_days)
        deleted = conn.execute(
            "DELETE FROM report_run WHERE completed_at < ?",
            (cutoff.isoformat(),)
        ).rowcount
        conn.commit()

    if deleted > 0:
        logger.info(f"[cleanup] Deleted {deleted} expired report_run records")

    _update_scheduler("last_cleanup_time", _now_iso())


# 注册清理任务（每日 08:00）
from apscheduler.triggers.cron import CronTrigger

scheduler.add_job(
    func=_run_cleanup,
    trigger=CronTrigger(hour=8, minute=0),
    id="daily_cleanup",
    replace_existing=True,
)
```

## 验收标准

| # | 验收项 | 验证方式 |
|---|--------|----------|
| 1 | 新情报（extracted=0）在 10 分钟内被抽取 | 插入测试情报，观察日志 |
| 2 | 抽取成功后 `extracted=1` | `SELECT extracted FROM intelligence` |
| 3 | 抽取失败后 `extracted=2` | 模拟 LLM 失败，验证状态 |
| 4 | `intel_fact` 表有数据 | `SELECT COUNT(*) FROM intel_fact` |
| 5 | `report_scheduler.last_extract_time` 持续更新 | 连续观察 2 次轮询 |
| 6 | 每日 08:00 清理执行 | 模拟时间到 08:00，验证删除逻辑 |

---

## 注意事项

1. **重试逻辑只在 `extracted=0` 时触发：** `extracted=2` 的记录不会再次尝试抽取，避免无限重试。如果用户需要重新抽取，可手动将 `extracted` 设为 0
2. **`extract_success_today` 在每天 00:00 重置：** 可考虑在 `_run_cleanup()` 中添加重置逻辑
