# P5.2 — 历史情报回填抽取

> **状态：** ⏳ 待开始
> **前置条件：** P2.2（抽取流程已实现）
> **依赖本任务的后续任务：** P6.1

---

## 目标

系统首次上线时，将所有已存在的情报（`intelligence` 表中所有记录）标记为待抽取，触发一次全量回填。

---

## 实施步骤

### Step 1：SQL 批量更新

在数据库初始化后（`init_db()` 之后）或手动执行一次 SQL：

```sql
-- 将所有情报标记为未抽取
UPDATE intelligence SET extracted = 0 WHERE extracted = 0 OR extracted IS NULL;
```

如果数据库中已存在 `extracted` 列但值为 NULL（老数据），以上 SQL 确保所有数据被标记为待抽取。

### Step 2：手动触发全量抽取

在系统启动后，通过 API 触发一次全量抽取：

```bash
# 方式一：通过 API
curl -X POST http://localhost:8766/api/reports/scheduler/run-all \
  -H "Authorization: Bearer <token>"

# 方式二：直接通过调度器
# 调度器每 10 分钟会自动检查 pending 情报
```

或者在 `init_db()` 末尾（种子数据灌入后）添加自动触发逻辑：

```python
# 在 init_db() 末尾，种子数据灌入后
import threading
def _async_backfill():
    import time
    time.sleep(5)  # 等待调度器启动
    from core.scheduler.extraction_engine import extract_all_pending
    result = extract_all_pending()
    print(f"[init_db] Backfill extraction done: {result}")

threading.Thread(target=_async_backfill, daemon=True).start()
```

### Step 3：确认回填完成

回填完成后验证：

```sql
-- 所有情报的抽取状态分布
SELECT extracted, COUNT(*) FROM intelligence GROUP BY extracted;

-- 预期结果：
-- 0  | 0    （没有未抽取的）
-- 1  | X    （成功抽取 X 条）
-- 2  | Y    （部分失败 Y 条）
```

## 验收标准

| # | 验收项 | 验证方式 |
|---|--------|----------|
| 1 | 所有情报被标记为 extracted=0 | `SELECT COUNT(*) FROM intelligence WHERE extracted=0` |
| 2 | 回填后所有情报 extracted=1 或 2 | `SELECT COUNT(*) FROM intelligence WHERE extracted IN (1,2)` = 总情报数 |
| 3 | `intel_fact` 表有大量数据 | `SELECT COUNT(*) FROM intel_fact` |
| 4 | 回填过程不阻塞服务启动 | 容器启动时间 < 30 秒 |

---

## 注意事项

1. **回填耗时估算：** 假设 200 条情报 × 2 条规则 = 400 次 LLM 调用，每次 60s 超时，理论上最多需要 400×60s / 60 = 400 分钟（串行）。建议设置更短的超时或先处理最新的情报
2. **分批处理策略：** 如果情报量大，可考虑每次处理 50 条，分多轮完成
3. **回填失败处理：** 回填过程中如果 LLM 不可用，失败的记录保持 `extracted=0`，下次轮询自动重试

---

## 回滚方案

- 恢复 `intelligence.extracted = 1`（将所有情报标记为已抽取）
- 或清空 `intel_fact` 表中的回填数据：`DELETE FROM intel_fact`
