# P5.1 — Docker 配置更新

> **状态：** ⏳ 待开始
> **前置条件：** P2.1（调度器框架已实现）
> **依赖本任务的后续任务：** P6.1

---

## 目标

修改 `docker-compose.yml` 和相关 Docker 配置，使调度器进程能在 `intelligence_web` 容器启动时自动运行。

---

## 实施步骤

### Step 1：修改 docker-compose.yml

找到 `intelligence_web` 服务的定义，添加调度器进程启动命令。

当前（假设）配置：

```yaml
intelligence_web:
    build:
        context: .
        dockerfile: intelligence_web/Dockerfile.api
    ports:
        - "8766:8766"
    # ...
```

修改为：

```yaml
intelligence_web:
    build:
        context: .
        dockerfile: intelligence_web/Dockerfile.api
    ports:
        - "8766:8766"
    command: >
        bash -c "
            python -m core.scheduler.scheduler &
            gunicorn -b 0.0.0.0:8766 wsgi:app
        "
    # 或者使用 entrypoint（根据项目现有方式选择）
```

### Step 2：修改 Dockerfile（如果需要）

确保 `Dockerfile.api` 中已包含新依赖（已在 P0.2 中完成），并确认 Python 包路径正确。

当前 `Dockerfile.api` 可能有：

```dockerfile
COPY intelligence_web /app
WORKDIR /app
```

确保 `core/` 目录也在 COPY 范围内：

```dockerfile
COPY core /app/core
COPY intelligence_web /app/intelligence_web
```

### Step 3：确认 scheduler 进程退出后不影响容器

使用 `bash -c "command1 & command2"` 模式：
- `command1`（scheduler）作为后台进程（`&` 结尾）
- `command2`（Flask/gunicorn）作为前台进程
- 容器生命周期由前台进程决定
- scheduler 退出时容器不会退出

## 验收标准

| # | 验收项 | 验证方式 |
|---|--------|----------|
| 1 | 容器启动后 Flask API 正常响应 | `curl localhost:8766` |
| 2 | 调度器进程在容器中运行 | `docker exec <container> ps aux` 确认有 `scheduler` 进程 |
| 3 | 调度器日志输出正常 | `docker logs <container>` 包含 "Scheduler started" |
| 4 | 停止调度器后 API 不受影响 | `kill` 调度器进程，API 仍响应 |

---

## 注意事项

1. **进程管理方式选择：** 根据项目现有 Dockerfile 的启动方式选择 `command` 或 `entrypoint`
2. **日志分离：** 如果需要分别查看两个进程的日志，考虑使用 `supervisord` 或分别输出到不同文件
3. **重启策略：** 调度器进程崩溃后由容器重启策略（`restart: always`）恢复
